1. Pendahuluan dan Apersepsi

"Pada bab sebelumnya, kita sudah belajar membuat komputer virtual. Sekarang, bagaimana cara mengubah komputer virtual tersebut menjadi server Linux yang benar-benar dapat digunakan?"

Di Bab 3, kamu sudah membuat Virtual Machine (VM). Tapi VM yang baru dibuat itu masih "kosong", seperti gedung baru yang belum ada perabotnya: ada ruangan (CPU, RAM, disk), tetapi belum ada sistem operasi yang mengatur semuanya. Di bab inilah kita "mengisi" gedung itu dengan Ubuntu Server.

Tujuan pembelajaran

Setelah mempelajari bab ini, kamu mampu:

  1. Menjelaskan fungsi Ubuntu Server.
  2. Menyiapkan kebutuhan instalasi sistem operasi server.
  3. Memahami pilihan partisi disk saat instalasi.
  4. Mengatur hostname server.
  5. Memahami konfigurasi jaringan server.
  6. Memahami fungsi OpenSSH Server dan opsi instalasinya.
  7. Menyelesaikan instalasi Ubuntu Server.
  8. Melakukan login ke server melalui terminal.
  9. Memverifikasi bahwa sistem berhasil diinstal.

Proyek mini kamu: membangun server bernama asj-server01 di dalam VM. Di akhir bab, kamu harus bisa membuka terminalnya, login, dan membuktikan dengan beberapa perintah bahwa server itu benar-benar hidup: nama hostnya benar, versi Ubuntu-nya terbaca, dan punya alamat IP. Hasilnya kamu dokumentasikan dalam laporan sederhana (lihat bagian Output Akhir).

2. Mengenal Ubuntu Server

Ubuntu adalah salah satu distribusi (distro) Linux yang dikembangkan oleh perusahaan Canonical bersama komunitas open source. Ubuntu tersedia dalam beberapa edisi; dua yang paling sering dibahas adalah Desktop dan Server.

Ubuntu Server adalah edisi Ubuntu yang dirancang untuk menjalankan layanan (web, file, database, dan sebagainya). Secara bawaan ia tidak memiliki tampilan grafis; kamu mengendalikannya lewat terminal berbasis teks. Contoh: ketika kamu membuka website sekolah, di belakangnya bisa saja ada Ubuntu Server yang menyajikan halaman itu.

Analogi: hardware, sistem operasi, dan aplikasi server

Bayangkan sebuah restoran. Hardware adalah gedung dan dapurnya. Sistem operasi (Ubuntu Server) adalah manajer yang mengatur siapa memakai kompor, kapan bahan diambil, dan menjaga kelancaran dapur. Aplikasi server (misalnya web server) adalah koki spesialis yang menyiapkan menu tertentu. Tanpa manajer, koki dan dapur tidak bisa bekerja teratur.

Fungsi sistem operasi pada server

  • Mengatur pemakaian CPU, RAM, dan disk oleh banyak proses.
  • Mengelola pengguna dan hak akses (siapa boleh melakukan apa).
  • Mengelola koneksi jaringan.
  • Menjadi "landasan" tempat aplikasi server dipasang.

Mengapa Linux banyak dipakai pada server?

Linux bersifat open source sehingga tidak memerlukan biaya lisensi sistem operasinya, dapat dikonfigurasi sangat fleksibel, bisa berjalan tanpa tampilan grafis, dan didukung komunitas besar. Ini alasan yang masuk akal, tetapi bukan berarti Linux (atau Ubuntu) otomatis lebih cepat atau lebih aman daripada sistem operasi lain. Kecepatan dan keamanan sangat bergantung pada kebutuhan, konfigurasi, dan cara administrator merawatnya.

Hubungan dengan pekerjaan System Administrator

Seorang System Administrator memasang, mengonfigurasi, memantau, dan merawat server. Instalasi sistem operasi adalah langkah pertama dari seluruh pekerjaan itu. Bab ini melatih fondasinya.

Contoh penggunaan Ubuntu Server

Sekolah

Server e-learning, file sharing, atau lab praktik jaringan.

Kantor

Server berkas bersama, server intranet, atau server backup.

Hosting

Menjalankan website dan aplikasi web pelanggan.

Data center

Menjadi dasar server fisik, VM, atau cloud skala besar.

Versi LTS. Untuk bab ini kita memakai Ubuntu Server 26.04 LTS (Resolute Raccoon), yang dirilis 23 April 2026 dan didukung hingga April 2031. LTS (Long Term Support) berarti rilis dengan dukungan pembaruan keamanan jangka panjang, sehingga cocok untuk server. Jika kelasmu memakai ISO 24.04 LTS, langkah dasarnya sangat mirip; perbedaan tampilan kecil akan disebut di tiap tahap.

3. Persiapan Instalasi

Sebelum memulai, pastikan semua bahan siap, seperti memeriksa bahan masakan sebelum memasak.

  • Laptop atau komputer — sebagai host (komputer asli yang menjalankan VM).
  • Oracle VirtualBox atau VMware Workstation — aplikasi virtualisasi dari Bab 3. Panduan di bab ini memakai istilah VirtualBox; VMware sangat mirip.
  • File ISO Ubuntu Server — media instalasi, diunduh dari situs resmi.
  • CPU dengan dukungan virtualisasi — fitur seperti Intel VT-x atau AMD-V harus aktif di BIOS/UEFI agar VM 64-bit berjalan baik.
  • RAM — sebagian RAM laptop akan "dipinjamkan" ke VM.
  • Ruang penyimpanan — untuk file ISO dan virtual disk VM.
  • Koneksi internet — dibutuhkan untuk mengunduh ISO, dan membantu installer mengambil pembaruan paket.
  • Pengetahuan dasar VM — cara membuat VM, mengatur RAM/CPU/disk, dan menjalankannya (Bab 3).

Apa itu file ISO?

ISO adalah satu file yang berisi salinan lengkap isi sebuah cakram instalasi (CD/DVD). Di komputer fisik, ISO biasanya dituliskan ke flashdisk bootable. Di VM, ISO cukup "dipasang" ke virtual optical drive seolah-olah itu DVD sungguhan. Contoh nama file untuk rilis ini: ubuntu-26.04-live-server-amd64.iso.

Cara memperoleh ISO dari situs resmi

  1. Buka ubuntu.com/download/server.
  2. Pilih rilis LTS yang ditentukan gurumu, lalu unduh Server install image untuk arsitektur amd64 (laptop Intel/AMD pada umumnya).
  3. Simpan di folder yang mudah ditemukan, misalnya Downloads/ISO.
  4. Alternatif: daftar semua rilis tersedia di releases.ubuntu.com. Di sana ada juga berkas SHA256SUMS untuk memeriksa checksum.

Catatan: ISO berukuran besar (beberapa GB), jadi unduh saat koneksi stabil. Waspadai situs tidak resmi yang menyediakan ISO, karena file bisa saja sudah diubah.

  • Koneksi internet tersedia.
  • Lembar kerja dokumentasi siap diisi.

4. Mempersiapkan Virtual Machine

Tampilan menu dapat sedikit berbeda antar versi VirtualBox atau VMware. Pahami fungsi tiap pengaturan, bukan sekadar menghafal letak tombolnya.

  1. 1. Buka VirtualBox/VMware. Pastikan aplikasi berjalan normal. Bila VM Bab 3 masih ada dan kosong (belum berisi OS), kamu boleh memakainya; jika ragu, buat VM baru agar bersih.
  2. 2. Buat VM baru (di VirtualBox: tombol New).
  3. 3. Beri nama VM, misalnya Ubuntu-Server-ASJ. Fungsi: pembeda antar VM di daftar. Hindari spasi berlebihan dan nama yang membingungkan.
  4. 4. Pilih tipe OS: Type Linux, Version Ubuntu (64-bit). Fungsi: VirtualBox menyesuaikan pengaturan bawaan dengan jenis OS. Bila VirtualBox versi 7 menampilkan opsi Skip Unattended Installation, centang opsi itu supaya kamu menjalani installer secara manual dan benar-benar belajar tiap langkahnya.
  5. 5. Atur RAM dan CPU (lihat rekomendasi di Bagian 3). Fungsi: menentukan "tenaga" VM. Terlalu kecil membuat installer gagal atau sangat lambat; terlalu besar membuat laptop macet.
  6. 6. Buat virtual disk (ukuran 20–25 GB, format VDI, dynamically allocated). Fungsi: "harddisk" milik VM yang sebenarnya hanyalah sebuah file di laptopmu. Gunakan hanya virtual disk baru ini. Jangan memilih disk fisik laptop.
  7. 7. Pasang ISO sebagai media boot. Buka Settings → Storage, klik ikon disk kosong (Empty) di bawah Controller, pilih Choose a disk file, lalu pilih file ISO Ubuntu Server. Fungsi: memberi tahu VM bahwa ada "DVD instalasi" di drive optiknya. Di Settings → System, pastikan urutan boot memuat Optical di atas Hard Disk.
  8. 8. Pilih mode jaringan awal (Settings → Network). Pilihan umum:
    • NAT: VM berada di jaringan privat milik VirtualBox dan biasanya bisa mengakses internet lewat laptop. Sederhana, tetapi VM tidak mudah diakses dari komputer lain.
    • Bridged Adapter: VM tampil seperti perangkat tersendiri di jaringan yang sama dengan laptop dan bisa memperoleh IP dari router/DHCP jaringan itu (bergantung kebijakan jaringan sekolah/Wi-Fi).
    • Host-only / Internal Network: jaringan terbatas untuk eksperimen; dipakai pada bab-bab berikutnya.
    Untuk Bab 4, NAT adalah pilihan awal yang aman. Jangan menganggap semua VM otomatis mendapat IP dari jaringan fisik; hasilnya dipengaruhi mode yang dipilih.
  9. 9. Periksa kembali konfigurasi. Cek nama, RAM, CPU, ukuran disk, ISO terpasang, dan mode jaringan sebelum dijalankan. Tangkap layar ringkasannya untuk dokumentasi.
  10. 10. Jalankan VM (tombol Start). Jendela VM akan terbuka dan installer Ubuntu mulai dimuat.

Tips: klik di dalam jendela VM untuk "menangkap" keyboard/mouse. Untuk mengeluarkan kursor dari VM, VirtualBox memakai tombol Host Key (bawaannya Right Ctrl). Mouse sering tidak berfungsi di installer teks; pakai keyboard.

5. Proses Instalasi Ubuntu Server

Installer Ubuntu Server berbasis teks. Navigasinya: panah atas/bawah berpindah pilihan, Tab berpindah antar bagian layar, Spasi mencentang kotak, Enter mengonfirmasi (tombol Done/Continue). Urutan dan nama layar dapat berbeda sedikit antar versi (24.04 vs 26.04); jika ada layar yang tidak muncul, baca tulisannya dan lanjutkan dengan pilihan paling aman.

A. Memulai installer

Saat VM menyala, ISO di-boot dan menu awal muncul. Pilih Try or Install Ubuntu Server, lalu tekan Enter. Tunggu teks bergulir; installer akan dimuat dan layar pertama (pemilihan bahasa) tampil. Pada beberapa versi muncul layar Installer update available; memilih memperbarui installer akan mengunduh versi baru dan mengulang proses di titik yang sama (butuh internet). Jika internet belum tersedia, pilih lanjut tanpa memperbarui.

B. Bahasa dan keyboard

Pilih bahasa (umumnya English, agar pesan error mudah dicari di internet) dan layout keyboard (laptop di Indonesia umumnya English (US)).

Tips: layout yang salah membuat simbol tertukar (misalnya @ dan "). Pada layar keyboard ada kolom uji ketik; coba ketik beberapa simbol sebelum lanjut. Hindari password dengan banyak simbol saat latihan, supaya kamu tidak terkunci karena salah layout.

Pilihan jenis instalasi

Biasanya ada Ubuntu Server (standar) dan Ubuntu Server (minimized) (lebih ringkas, umumnya untuk cloud/kontainer). Untuk latihan pilih Ubuntu Server standar.

C. Network Configuration

  • Network interface: "port" jaringan milik komputer (di VM berupa kartu jaringan virtual). Contoh nama: enp0s3 (nama bisa berbeda).
  • IP Address: "alamat rumah" komputer di jaringan, misalnya 10.0.2.15 (contoh umum pada mode NAT VirtualBox).
  • DHCP: layanan yang otomatis membagikan IP dan pengaturan jaringan ke perangkat yang meminta. Cara kerja sederhananya: perangkat "berteriak" meminta alamat, server DHCP menjawab dengan alamat yang tersedia, lalu perangkat memakainya untuk sementara waktu.
  • IP statis: alamat yang kamu tetapkan manual. Berguna untuk server yang alamatnya harus tetap, tetapi mudah salah jika belum paham pengalamatan.

Cara membaca layar jaringan: installer menampilkan daftar interface. Jika DHCP berhasil, di samping interface terlihat metode DHCPv4 beserta alamat IP-nya (catat alamat itu). Jika masih menunggu, tunggu beberapa detik. Jika tetap kosong, lihat bagian Troubleshooting.

Untuk praktikum awal gunakan DHCP bila tersedia. Konfigurasi manual diperlukan bila jaringan tidak memiliki DHCP atau server wajib berada di alamat tertentu. Hasilnya bisa berbeda tergantung versi installer dan lingkungan virtualisasi: pada NAT biasanya VM mendapat IP privat dari VirtualBox, sedangkan pada Bridged IP berasal dari jaringan fisik (jika jaringan itu mengizinkan).

Istilah lain yang akan sering kamu temui: gateway (pintu keluar menuju jaringan lain, mis. internet) dan DNS (penerjemah nama seperti ubuntu.com menjadi alamat IP). Konfigurasi manualnya baru dipelajari di bab berikutnya.

D. Proxy Configuration

Proxy adalah perantara antara komputer dan internet; beberapa jaringan kantor atau sekolah mewajibkan lalu lintas internet melewatinya. Contoh: jaringan sekolah yang memfilter situs lewat server proxy. Jika jaringanmu tidak memakai proxy, biarkan kolom kosong lalu pilih Done. Isi hanya jika gurumu memberi alamat proxy.

E. Ubuntu Archive Mirror

Repository adalah gudang paket perangkat lunak Ubuntu, dan mirror adalah salinan gudang itu di server lain agar unduhan lebih dekat dan cepat. Installer membutuhkan sumber paket ini untuk mengambil pembaruan dan komponen tambahan. Installer biasanya memilih mirror bawaan sesuai lokasi dan mengujinya; jika tes lulus, pilih Done.

Jika mirror tidak dapat dijangkau: periksa koneksi internet (kembali ke layar jaringan), cek apakah memakai proxy, lalu coba mirror lain atau ulangi beberapa saat kemudian. Jika memang tidak ada internet, instalasi dasar dari ISO masih dapat dilanjutkan, dan pembaruan bisa dilakukan nanti setelah jaringan siap.

F. Storage Configuration dan Partisi Disk

  • Disk: perangkat penyimpan data (fisik, atau file virtual pada VM).
  • Partisi: bagian terpisah dari sebuah disk, seperti sekat ruangan dalam satu gedung.
  • Filesystem: aturan penataan data dalam sebuah partisi, seperti sistem rak dan label di lemari arsip (contoh: ext4).
  • Mount point: "pintu" tempat sebuah partisi dipasang ke struktur direktori Linux.
  • Root filesystem /: titik awal seluruh pohon direktori; semua folder lain berada di bawahnya.
  • /boot: tempat file yang dipakai saat proses booting (kernel). Pada beberapa susunan ia berupa partisi terpisah; pada pengaturan otomatis installer akan mengaturnya sesuai kebutuhan.
  • Swap: ruang di disk yang dipakai sebagai "cadangan" RAM ketika memori hampir penuh. Lebih lambat dari RAM. Ubuntu dapat memakai file atau partisi swap tergantung pengaturan dan versi.

Analogi: disk itu seperti sebuah lemari besar. Partisi adalah rak-raknya, filesystem adalah aturan cara menyusun barang di rak, dan mount point adalah label pintu rak agar mudah dicari. Swap seperti kardus tambahan di gudang ketika meja kerjamu (RAM) sudah penuh.

Virtual disk vs disk fisik: virtual disk hanyalah sebuah file di laptop, sehingga jika salah, tinggal buat ulang. Disk fisik adalah perangkat sungguhan; salah konfigurasi dapat menghapus data penting.

Untuk siswa pemula di VM: pilih konfigurasi otomatis pada virtual disk baru dan biarkan pengaturan bawaan. Setelah itu installer menampilkan ringkasan penyimpanan. Baca ringkasan itu: pastikan hanya ada satu disk dengan ukuran sesuai virtual disk yang kamu buat. Pilih Done, lalu konfirmasi dengan Continue pada peringatan.

Peringatan penting: konfigurasi storage yang salah pada komputer fisik dapat menghapus data. Jangan mengubah partisi komputer utamamu. Semua latihan partisi dilakukan hanya pada virtual disk khusus yang tidak berisi data penting. Setelah kamu menekan Continue pada konfirmasi, disk tujuan akan dihapus dan diformat.

G. Profile Setup

  • Your name: nama tampilan pemilik akun (boleh nama lengkap).
  • Your server's name (hostname): nama identitas server di jaringan. Contoh latihan: asj-server01. Aturan praktis: huruf kecil, angka, dan tanda hubung, tanpa spasi, mudah dikenali.
  • Username: nama akun untuk login. Contoh latihan: khalid atau adminlab.
  • Password: kata sandi akun tersebut. Installer meminta kamu mengetiknya dua kali untuk konfirmasi.

Semua contoh di atas hanya untuk latihan; pakai nama sesuai instruksi gurumu bila berbeda.

Hostname vs username: hostname adalah nama komputernya (siapa servernya), sedangkan username adalah nama orangnya yang masuk. Analogi: hostname seperti nama gedung, username seperti nama pegawai yang masuk ke gedung itu. Pada prompt khalid@asj-server01, khalid adalah username dan asj-server01 adalah hostname.

Aturan password yang kuat

  • Cukup panjang (disarankan 12 karakter atau lebih) dan tidak mudah ditebak.
  • Campur huruf besar/kecil, angka; simbol boleh tetapi pastikan layout keyboard benar.
  • Jangan memakai nama, tanggal lahir, atau password akun pribadimu (e-mail, media sosial).
  • Jangan menuliskan password di laporan, dokumentasi, atau screenshot.
  • Catat password latihan di tempat aman yang hanya kamu ketahui, bukan di grup kelas.

H. Ubuntu Pro dan opsi tambahan

Ubuntu Pro adalah layanan berlangganan dari Canonical yang menambah cakupan pembaruan keamanan (pada paket tertentu) dan fitur kepatuhan. Pada beberapa versi installer, layar ini muncul. Untuk latihan di sekolah, kamu tidak wajib mendaftar: pilih Skip for now (atau opsi serupa) lalu lanjut.

I. SSH Setup

  • SSH (Secure Shell): protokol untuk masuk dan mengendalikan komputer lain lewat jaringan secara terenkripsi. OpenSSH adalah perangkat lunak yang mengimplementasikannya. Pada server, bagian yang "menunggu tamu" disebut OpenSSH Server.
  • Login lokal vs remote: login lokal berarti kamu duduk di depan layar/konsol server (atau VM). Login remote berarti masuk dari komputer lain lewat jaringan.
  • Mengapa berguna untuk ASJ: administrator jarang berdiri di depan server; mereka mengelolanya dari jauh. Dengan SSH kamu bisa menyalin perintah, memakai terminal host yang lebih nyaman, dan berlatih seperti kondisi nyata.
  • Kapan opsi ini dipilih: centang Install OpenSSH server jika opsi tersedia dan kelas membutuhkannya. Bab ini tidak mengharuskan koneksi SSH berhasil, tetapi memasangnya sekarang memudahkan bab berikutnya. Pada instalasi bawaan Ubuntu, tanpa opsi ini tidak ada port yang terbuka untuk SSH.

Keberhasilan SSH juga bergantung pada layanan SSH yang berjalan, alamat IP yang benar, aturan firewall, dan konektivitas jaringan (misalnya pada mode NAT, host tidak bisa langsung menjangkau VM tanpa pengaturan tambahan). Jangan membuka akses server ke internet publik tanpa kebutuhan dan pengamanan yang sesuai.

J. Featured Server Snaps

Snap adalah format paket aplikasi. Jika ada koneksi jaringan, installer dapat menampilkan daftar snap populer untuk server (misalnya alat kontainer atau database). Untuk Bab 4, jangan pilih apa pun: kita belum membutuhkan layanan tambahan, dan menambah paket membuat instalasi lebih lama. Pilih Done tanpa mencentang.

K. Instalasi selesai

Setelah konfirmasi, installer menyalin sistem ke disk, memasang paket, dan (jika internet ada) memasang pembaruan keamanan. Layar menampilkan log yang bergulir. Tunggu sampai muncul pesan Install complete! dan tombol Reboot Now. Jangan mematikan VM paksa selama proses berlangsung.

Melepas ISO: setelah restart, VM harus boot dari virtual disk, bukan dari ISO lagi. Biasanya installer meminta kamu melepas media instalasi lalu menekan Enter. Di VirtualBox kamu bisa memakai menu Devices → Optical Drives → Remove disk from virtual drive (atau melepasnya di Settings → Storage saat VM mati). Jika tidak dilepas dan VM kembali masuk installer, matikan VM, lepas ISO, lalu jalankan lagi.

L. Login pertama

Setelah reboot dan teks booting selesai, kamu akan melihat prompt login. Ketik username lalu Enter, kemudian ketik password lalu Enter.

Jangan panik: saat mengetik password di terminal Linux, karakter biasanya tidak tampil sama sekali (tidak ada bintang atau titik). Itu bukan berarti keyboard rusak; itu fitur keamanan. Ketik dengan tenang lalu tekan Enter.

Contoh sesi (ilustrasi; tampilan bisa berbeda pada versi lain):

asj-server01 login: khalid
Password:            <-- tidak ada karakter yang tampil
...
khalid@asj-server01:~$

Membaca prompt khalid@asj-server01:~$

  • khalid — username yang sedang aktif.
  • @ — "di", pemisah antara pengguna dan komputer.
  • asj-server01 — hostname server.
  • ~ — direktori aktif; tanda ini berarti home directory milik pengguna.
  • $ — tanda siap menerima perintah sebagai pengguna biasa (bukan administrator penuh).

6. Mengenal Terminal dan Verifikasi Instalasi

Terminal adalah jendela tempat kamu mengetik perintah untuk dikerjakan komputer. Di bab ini kamu hanya memakai perintah membaca informasi (aman, tidak mengubah sistem). Semua perintah Linux lainnya dipelajari di Bab 5.

Output di bawah hanyalah contoh ilustrasi. Hasil di komputermu bisa berbeda (nama interface, angka, versi kernel, ukuran disk) dan itu normal.

whoami — memeriksa username aktif

$ whoami
khalid

Menampilkan nama akun yang sedang kamu pakai.

hostname — memeriksa nama server

$ hostname
asj-server01

Harus sama dengan hostname yang kamu isi di installer.

pwd — melihat lokasi direktori aktif

$ pwd
/home/khalid

Singkatan dari print working directory. Menunjukkan "kamu sedang berada di folder mana".

ip a — memeriksa interface dan alamat IP

$ ip a
1: lo: <LOOPBACK,UP,LOWER_UP> ...
    inet 127.0.0.1/8 scope host lo
2: enp0s3: <BROADCAST,MULTICAST,UP,LOWER_UP> ...
    inet 10.0.2.15/24 ... scope global enp0s3

lo adalah interface internal milik komputer itu sendiri (loopback, selalu 127.0.0.1). Interface lain (misalnya enp0s3) adalah kartu jaringan; baris inet berisi alamat IPv4 dan angka setelah garis miring adalah panjang prefix jaringan. Jika interface UP tetapi tidak ada baris inet, berarti belum mendapat alamat IPv4.

df -h — memeriksa kapasitas penyimpanan

$ df -h
Filesystem   Size  Used Avail Use% Mounted on
/dev/...      12G  3.5G  7.5G  32% /

Opsi -h membuat ukuran mudah dibaca (G, M). Kolom Mounted on menunjukkan mount point; baris dengan / adalah root filesystem. Kapasitas yang terlihat bisa lebih kecil dari ukuran virtual disk karena pembagian oleh installer (misalnya struktur LVM) dan ruang sistem.

free -h — memeriksa penggunaan memori

$ free -h
               total   used   free  ...
Mem:           1.9Gi  250Mi  1.2Gi
Swap:          ...

Baris Mem menunjukkan RAM yang dikenali sistem; angkanya sedikit lebih kecil dari RAM yang kamu atur di VM karena sebagian dipakai sistem. Baris Swap menunjukkan ruang swap (bisa nol bila tidak ada).

uname -r — memeriksa versi kernel

$ uname -r
<versi-kernel>-generic

Kernel adalah inti sistem operasi yang berhubungan langsung dengan hardware. Nomor versinya berbeda tiap rilis Ubuntu dan tiap pembaruan.

cat /etc/os-release — memeriksa versi Ubuntu

$ cat /etc/os-release
PRETTY_NAME="Ubuntu 26.04 LTS"
NAME="Ubuntu"
VERSION_ID="26.04"
...

cat menampilkan isi file; /etc/os-release adalah file berisi identitas sistem operasi. Perhatikan PRETTY_NAME dan VERSION_ID.

Pemeriksaan jaringan yang aman

$ ip route
default via 10.0.2.2 dev enp0s3 ...

$ ping -c 4 8.8.8.8
$ ping -c 4 ubuntu.com
  • ip route menampilkan jalur jaringan; baris default via menunjukkan gateway.
  • ping -c 4 8.8.8.8 mengirim 4 paket uji ke sebuah alamat IP internet. Jika berhasil, jalur ke internet bekerja. Opsi -c 4 membatasi jumlah paket agar perintah berhenti sendiri.
  • ping -c 4 ubuntu.com menguji sekaligus penerjemahan nama (DNS). Jika ping ke IP berhasil tetapi ke nama gagal, kemungkinan masalah ada pada DNS. Pada sebagian jaringan, ping sengaja diblokir, jadi gagal ping belum tentu berarti tidak ada internet.

Cara memeriksa shutdown yang benar

Untuk mematikan server dengan benar dari terminal, gunakan sudo poweroff (sudo berarti menjalankan sebagai administrator sementara, dan akan meminta password akunmu). Hindari menekan tombol power secara paksa. Jangan menjalankan perintah yang menghapus file atau mengubah konfigurasi sebelum kamu memahaminya.

9. Studi Kasus

Coba jawab sendiri dulu, lalu buka petunjuk dan pembahasan.

Kasus 1 — Memilih disk yang salah

Seorang siswa hampir menekan Continue pada konfirmasi storage, namun baru sadar ada dua disk di daftar dan ia tidak yakin mana yang virtual disk latihan. Pertanyaan: Apa tindakan pencegahan yang seharusnya dilakukan?

Petunjuk & pembahasan

Petunjuk: Ukuran disk dan sumber disk bisa menjadi pembeda.

Pembahasan: Berhenti dulu dan jangan lanjut sebelum yakin. Bandingkan ukuran dan nama disk dengan virtual disk yang dibuat di VM; pada VM latihan seharusnya hanya ada satu disk virtual. Jika ada disk lain, tanyakan guru. Pencegahan: tulis ukuran virtual disk di lembar kerja sebelum memulai, dan selalu baca ringkasan storage sebelum Continue. Pada komputer fisik, jangan latihan di disk yang berisi data.

Kasus 2 — Login berhasil tetapi tidak ada IP Address

Sebuah VM bisa login, tetapi ip a hanya menampilkan lo dengan 127.0.0.1, sedangkan interface lain tanpa alamat. Pertanyaan: Apa penyebab yang mungkin dan apa yang diperiksa?

Petunjuk & pembahasan

Petunjuk: Periksa pengaturan adapter jaringan VM dan status interface.

Pembahasan: Kemungkinan adapter jaringan VM dinonaktifkan atau kabel virtual tidak terhubung, mode jaringan tidak menyediakan DHCP, atau interface belum terkonfigurasi untuk DHCP. Matikan VM, cek Settings → Network (adapter aktif, coba NAT), jalankan lagi, dan periksa ulang ip a. Memperbaiki konfigurasi jaringan secara manual dipelajari pada bab-bab berikut.

Kasus 3 — Lupa hostname

Seorang siswa akan mengisi laporan dokumentasi, tetapi lupa hostname yang ia pakai. Pertanyaan: Bagaimana cara mengetahuinya tanpa menginstal ulang?

Petunjuk & pembahasan

Petunjuk: Lihat prompt terminal atau perintah yang menampilkan nama server.

Pembahasan: Login, lalu lihat prompt (username@hostname:~$) atau jalankan hostname. Tidak perlu instal ulang. Pelajaran: dokumentasikan hostname sejak awal.

Kasus 4 — VM terus masuk ke installer setelah restart

Instalasi sudah selesai dan VM restart, tetapi yang muncul lagi layar awal installer. Pertanyaan: Mengapa terjadi dan bagaimana mengatasinya?

Petunjuk & pembahasan

Petunjuk: Dari mana VM melakukan boot?

Pembahasan: ISO masih terpasang di virtual optical drive dan diprioritaskan saat boot. Matikan VM, lepas ISO (Settings → Storage) atau ubah urutan boot agar Hard Disk di atas, lalu jalankan lagi. Pastikan juga instalasi benar-benar selesai sebelum restart.

Kasus 5 — Bisa login lokal, tetapi SSH belum berhasil

Siswa dapat login di jendela VM, tetapi ketika mencoba terhubung lewat SSH dari laptop, koneksi gagal. VM memakai mode NAT. Pertanyaan: Faktor apa yang perlu diperiksa?

Petunjuk & pembahasan

Petunjuk: Ada beberapa lapis: layanan, alamat, jalur jaringan, firewall.

Pembahasan: (1) Apakah OpenSSH Server terpasang saat instalasi? (2) Berapa IP VM dari ip a? (3) Pada NAT, VM berada di jaringan privat sehingga host tidak langsung menjangkaunya; dibutuhkan port forwarding atau mode lain seperti Bridged/Host-only. (4) Apakah ada firewall? Jangan membuka akses ke internet publik untuk "memaksa" bisa. Konfigurasi SSH lebih lanjut dipelajari kemudian.

Kasus 6 — Instalasi sangat lambat dan hampir berhenti

VM diberi RAM sangat kecil (512 MB) dan installer macet. Pertanyaan: Apa yang perlu diubah?

Petunjuk & pembahasan

Petunjuk: Bandingkan dengan kebutuhan yang disebutkan dokumentasi.

Pembahasan: Dokumentasi menyebut minimum sekitar 1,5 GB RAM untuk instalasi dari ISO dan menyarankan 3 GB atau lebih. Matikan VM, naikkan RAM (misalnya 2 GB atau lebih sesuai kemampuan laptop), lalu ulangi.

10. Tips Administrator Pemula

  1. Unduh ISO hanya dari situs resmi. File dari sumber tidak jelas bisa saja sudah dimodifikasi.
  2. Periksa checksum bila tersedia. Checksum (misalnya SHA256) membuktikan file utuh dan tidak berubah; berkas SHA256SUMS tersedia di situs rilis.
  3. Buat snapshot VM sebelum eksperimen penting. Snapshot memungkinkan kembali ke kondisi sehat jika percobaan gagal.
  4. Pilih hostname yang mudah dikenali (asj-server01), agar tidak tertukar ketika server makin banyak.
  5. Catat konfigurasi IP beserta mode jaringan, supaya mudah diperiksa saat ada masalah.
  6. Jaga kerahasiaan password dan jangan memakai password pribadi untuk latihan.
  7. Periksa konfigurasi sebelum menekan konfirmasi storage. Pada tahap itu disk tujuan akan diformat.
  8. Simpan dokumentasi instalasi (screenshot ringkasan, catatan langkah), karena memudahkan penelusuran dan pengulangan.
  9. Jangan sembarangan memakai sudo. Perintah dengan hak administrator bisa mengubah atau merusak sistem; pahami dulu apa yang dilakukan perintah.
  10. Matikan server dengan benar (sudo poweroff), bukan mematikan paksa, agar data tidak rusak.
  11. Baca pesan di layar installer. Banyak kesalahan dapat dicegah dengan membaca peringatan.
  12. Ubah satu hal pada satu waktu saat troubleshooting, supaya penyebab masalah mudah diketahui.

11. Ringkasan

  • Ubuntu Server: edisi Ubuntu (Linux) untuk menjalankan layanan, umumnya tanpa tampilan grafis dan dikelola lewat terminal. Rilis LTS cocok karena didukung lama (26.04 LTS sampai April 2031).
  • Persiapan: laptop, VirtualBox/VMware, ISO resmi, virtualisasi CPU aktif, RAM dan ruang disk cukup, internet, checklist.
  • File ISO: salinan media instalasi dalam satu file; dipasang ke drive optik virtual.
  • Virtual Machine: komputer virtual dengan CPU, RAM, virtual disk, dan jaringan yang diatur; aman untuk berlatih.
  • Partisi dan filesystem: partisi membagi disk, filesystem mengatur data, mount point menghubungkan ke struktur direktori; / adalah root. Pemula memakai konfigurasi otomatis pada virtual disk baru.
  • Hostname: nama server (contoh asj-server01), berbeda dari username.
  • Network, DHCP, dan IP Address: IP adalah alamat di jaringan; DHCP memberikannya otomatis; IP statis diatur manual; hasil bergantung mode NAT/Bridged.
  • OpenSSH Server: memungkinkan login remote terenkripsi; dipilih saat instalasi bila dibutuhkan, tetapi keberhasilan tergantung layanan, IP, firewall, dan jaringan.
  • Proses instalasi: boot ISO → bahasa/keyboard → jaringan → proxy → mirror → storage → profil → Pro (opsional) → SSH → snaps (lewati) → instal → reboot dan lepas ISO.
  • Login terminal: password tidak tampil saat diketik; prompt user@host:~$.
  • Verifikasi sistem: whoami, hostname, pwd, ip a, df -h, free -h, uname -r, cat /etc/os-release.
  • Troubleshooting dasar: periksa dulu hal sederhana (ISO, urutan boot, adapter jaringan, layout keyboard) sebelum instal ulang.

    16. Glosarium

    Ubuntu Server — edisi Ubuntu untuk menjalankan layanan, umumnya tanpa tampilan grafis.

    LTS — Long Term Support, rilis dengan dukungan pembaruan jangka panjang.

    ISO — satu file berisi salinan isi media instalasi.

    Installer — program yang memandu pemasangan sistem operasi.

    Virtual Machine — komputer virtual yang berjalan di dalam komputer fisik.

    Host — komputer fisik yang menjalankan VM.

    Guest — sistem operasi/VM yang berjalan di dalam host.

    CPU — prosesor, "otak" yang mengeksekusi instruksi.

    RAM — memori sementara tempat data yang sedang diproses.

    Virtual disk — harddisk virtual milik VM yang berupa file di host.

    Disk — perangkat penyimpan data permanen.

    Partisi — bagian terpisah dari sebuah disk.

    Filesystem — aturan penataan dan penyimpanan data pada partisi.

    Mount point — direktori tempat partisi dipasang ke struktur folder.

    Root filesystem (/) — titik awal seluruh struktur direktori Linux.

    Swap — ruang disk yang dipakai sebagai cadangan saat RAM penuh.

    LVM — Logical Volume Management, cara fleksibel mengatur ruang disk; sering menjadi pilihan penyimpanan otomatis.

    Hostname — nama identitas komputer/server di jaringan.

    Username — nama akun pengguna untuk login.

    Password — kata sandi untuk membuktikan identitas pemilik akun.

    IP Address — alamat numerik perangkat di jaringan.

    DHCP — layanan yang membagikan alamat IP dan pengaturan jaringan otomatis.

    Network interface — antarmuka/kartu jaringan tempat IP dipasang.

    NAT — mode jaringan VM yang berbagi koneksi host lewat jaringan privat.

    Bridged — mode VM tampil sebagai perangkat sendiri di jaringan fisik.

    DNS — sistem penerjemah nama domain menjadi alamat IP.

    Gateway — pintu keluar menuju jaringan lain, mis. internet.

    Proxy — perantara antara komputer dan internet.

    SSH — protokol akses jarak jauh yang terenkripsi.

    OpenSSH — perangkat lunak yang mengimplementasikan SSH.

    Terminal — antarmuka teks untuk mengetik perintah.

    Prompt — teks penanda terminal siap menerima perintah.

    Kernel — inti sistem operasi yang berhubungan langsung dengan hardware.

    Repository — gudang paket perangkat lunak.

    Mirror — salinan repository di server lain untuk unduhan lebih cepat.

    Boot — proses menyalakan komputer dan memuat sistem operasi.

    Reboot — memulai ulang komputer.

    Login — proses masuk ke sistem dengan akun dan password.

    Checksum — nilai pemeriksa keutuhan file.

    Snapshot — rekaman kondisi VM pada satu waktu agar dapat dikembalikan.

    Snap — format paket aplikasi yang dipakai Ubuntu.

    Ubuntu Pro — layanan berlangganan tambahan untuk keamanan dan kepatuhan.

    Troubleshooting — proses mencari dan memperbaiki penyebab masalah secara sistematis.
