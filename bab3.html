Virtualisasi

Output: Siswa mampu membuat dan menjalankan Virtual Machine sebagai fondasi sebelum instalasi Ubuntu Server.

1. Pendahuluan

Bagaimana jika satu komputer bisa menjalankan beberapa komputer sekaligus?

Coba bayangkan: satu laptop yang kamu pakai sehari-hari bisa menjalankan Windows, Ubuntu Server, dan Debian secara bersamaan, seolah-olah kamu punya tiga komputer berbeda — padahal hardware fisiknya cuma satu. Tidak masuk akal? Justru inilah yang setiap hari dilakukan jutaan teknisi IT di seluruh dunia, dan teknologinya bernama virtualisasi.

Di Bab 2, kamu sudah belajar tentang hardware dan sistem operasi server. Sekarang muncul masalah praktis: bagaimana caranya kamu bisa belajar Ubuntu Server tanpa harus membeli komputer fisik baru, tanpa takut merusak laptop pribadimu, dan tanpa harus bolak-balik install ulang setiap kali salah konfigurasi? Jawabannya ada di Bab 3 ini.

Kenapa ini penting? Mulai Bab 4, kamu akan mulai meng-install Ubuntu Server sungguhan. Supaya proses belajar itu aman, murah, dan bisa diulang berkali-kali tanpa risiko, kita akan menjalankan Ubuntu Server itu di dalam sebuah Virtual Machine — bukan langsung di laptop fisikmu. Bab 3 inilah yang mengajarkanmu caranya.

Perjalanan belajar kita di bab ini: dari memahami apa itu komputer virtual, mengenal hypervisor yang mengaturnya, mencoba software VirtualBox/VMware, sampai akhirnya kamu benar-benar membuat Virtual Machine pertamamu sendiri — siap dipakai untuk instalasi Ubuntu Server di Bab 4.

2. Apa itu Virtualisasi?

Virtualisasi adalah teknologi yang memungkinkan satu perangkat keras (hardware) fisik "dipecah" atau dibagi menjadi beberapa komputer yang berjalan secara independen, seolah-olah masing-masing adalah komputer terpisah — padahal semuanya berbagi hardware fisik yang sama.

Mengapa virtualisasi dibuat, dan masalah apa yang diselesaikannya?

Dulu, setiap kali sebuah perusahaan butuh satu server untuk satu keperluan (misalnya satu untuk web, satu untuk database, satu untuk email), mereka harus membeli satu unit hardware fisik untuk masing-masing. Padahal kenyataannya, banyak server fisik itu hanya terpakai 10–20% dari kemampuannya — sisanya menganggur, tapi tetap memakan listrik, ruang, dan biaya perawatan. Virtualisasi lahir untuk menjawab pemborosan ini: satu hardware fisik yang kuat bisa "dibagi" menjadi banyak komputer virtual, masing-masing dipakai untuk keperluan berbeda, sehingga hardware benar-benar dimanfaatkan secara maksimal.

Analogi: Bayangkan satu gedung apartemen. Gedung itu adalah "hardware fisik", sedangkan setiap unit kamar di dalamnya adalah "komputer virtual". Setiap penghuni kamar merasa punya rumah sendiri — punya pintu sendiri, kunci sendiri, ruang sendiri — padahal mereka semua berbagi satu gedung, satu jaringan listrik, dan satu sistem air yang sama.

Cara Kerja Virtualisasi (Sederhana)

Sebuah software khusus (disebut hypervisor, akan dibahas di bagian selanjutnya) dipasang pada hardware fisik. Software ini bertugas "membagi-bagi" resource fisik (CPU, RAM, storage) menjadi beberapa bagian, lalu menciptakan komputer-komputer virtual dari bagian-bagian tersebut. Setiap komputer virtual ini punya sistem operasinya sendiri, aplikasinya sendiri, dan berjalan seolah-olah terpisah total dari komputer virtual lainnya.

Istilah Penting

Physical Machine

Komputer fisik sungguhan — ada bentuknya, bisa kamu sentuh, seperti laptop atau server rack yang dipelajari di Bab 2.

Virtual Machine (VM)

"Komputer" yang dibuat oleh software, tidak berbentuk fisik, tetapi berperilaku persis seperti komputer sungguhan.

Host

Komputer fisik yang "menampung" dan menjalankan Virtual Machine di dalamnya. Contoh: laptopmu adalah host.

Guest

Sistem operasi yang berjalan di dalam Virtual Machine. Contoh: Ubuntu Server yang kamu install di dalam VM adalah guest.

3. Mengapa Virtualisasi Penting?

  • Menghemat hardware & biaya — satu server fisik yang kuat bisa menggantikan banyak server fisik terpisah, mengurangi biaya pembelian dan listrik.
  • Efisiensi penggunaan resource — resource hardware yang tadinya menganggur bisa dimanfaatkan maksimal oleh banyak VM sekaligus.
  • Memudahkan pengujian — ingin mencoba software atau konfigurasi baru yang berisiko? Coba dulu di VM, tanpa mengganggu sistem utama.
  • Memudahkan pembelajaran — siswa bisa belajar Linux Server, jaringan, bahkan "merusak" sistem sesuka hati di VM tanpa takut merusak laptop sungguhan.
  • Isolasi sistem — masalah di satu VM (misalnya crash atau virus) tidak akan menyebar ke VM lain maupun ke host, karena masing-masing terisolasi.
  • Snapshot — bisa menyimpan "kondisi" VM pada waktu tertentu, dan kembali ke kondisi itu kapan saja (dibahas lebih dalam di bagian selanjutnya).
  • Clone — VM yang sudah dikonfigurasi bisa diduplikasi menjadi VM baru dengan cepat, tanpa perlu setup dari nol berulang kali.
  • Backup lebih mudah — VM pada dasarnya hanyalah kumpulan file di storage host, sehingga jauh lebih mudah dicadangkan dibanding komputer fisik utuh.
  • Laboratorium virtual & pengembangan/testing — tim developer bisa membuat "lab" berisi banyak server virtual untuk simulasi sebelum diterapkan ke server produksi sungguhan.

Contoh Nyata Penerapan Virtualisasi

Sekolah: siswa belajar Linux Server di VM tanpa perlu komputer fisik terpisah untuk tiap siswa.
Laboratorium komputer: satu ruang lab bisa mensimulasikan puluhan skenario jaringan berbeda dengan VM.
Perusahaan: banyak aplikasi bisnis berjalan di server virtual berbeda di atas beberapa server fisik saja.
Data center: ribuan VM disewakan ke banyak pelanggan berbeda di atas hardware fisik yang sama.
Cloud computing: layanan seperti AWS, Google Cloud, dan Azure pada dasarnya menjual "sewa" Virtual Machine kepada penggunanya di seluruh dunia — inilah fondasi bisnis cloud modern.

4. Hypervisor

Hypervisor (disebut juga Virtual Machine Monitor/VMM) adalah software yang bertugas menciptakan, menjalankan, dan mengatur Virtual Machine. Hypervisor inilah yang membagi-bagi resource hardware fisik (CPU, RAM, storage) ke setiap VM, serta memastikan satu VM tidak "mengganggu" VM lainnya.

Mengapa hypervisor diperlukan?

Tanpa hypervisor, sistem operasi tidak tahu caranya berbagi hardware dengan sistem operasi lain secara aman dalam satu waktu. Hypervisor bertindak sebagai "penengah" yang mengatur jadwal, alokasi resource, dan menjaga agar setiap VM tetap terisolasi satu sama lain — persis seperti kepala sekolah yang mengatur jadwal pemakaian lab komputer supaya tidak bentrok antar kelas.

Dua Jenis Hypervisor

Type 1 Hypervisor (Bare-Metal)

Hypervisor yang terpasang langsung di atas hardware fisik, tanpa memerlukan sistem operasi host di bawahnya. Karena "menempel langsung ke logam" (bare-metal), performanya sangat tinggi dan cocok untuk server produksi skala besar. Contoh: VMware ESXi, Microsoft Hyper-V (versi server), Proxmox VE.

Type 2 Hypervisor (Hosted)

Hypervisor yang terpasang sebagai aplikasi biasa di atas sistem operasi host yang sudah ada (misalnya Windows atau macOS). Lebih mudah dipakai untuk belajar dan testing karena tinggal install seperti aplikasi lain. Contoh: Oracle VirtualBox, VMware Workstation.

Penting untuk kelas ini: VirtualBox dan VMware Workstation yang akan kamu pakai untuk praktik adalah contoh virtualisasi desktop bertipe Type 2 — dipasang di atas sistem operasi laptop/PC-mu yang sudah ada.

5. Komponen Virtual Machine

Sama seperti komputer fisik yang punya CPU, RAM, dan storage, Virtual Machine juga punya "versi virtual" dari komponen-komponen tersebut. Berikut komponen penting yang akan kamu atur setiap kali membuat VM baru:

vCPU (Virtual CPU)

Jumlah "jatah" prosesor host yang dialokasikan untuk VM. Analogi: vCPU = otak — semakin banyak vCPU, semakin banyak tugas yang bisa dipikirkan/dikerjakan VM secara bersamaan.

vRAM (Virtual RAM)

Jumlah memori host yang dialokasikan untuk VM. Analogi: vRAM = meja kerja — semakin luas meja, semakin banyak "berkas" (proses) yang bisa dikerjakan sekaligus tanpa harus bongkar-pasang.

Virtual Disk

File khusus di storage host yang berperan sebagai "harddisk" VM. Analogi: Virtual Disk = lemari penyimpanan — tempat VM menyimpan sistem operasi, aplikasi, dan datanya sendiri.

Virtual Network Adapter

"Kartu jaringan" versi virtual yang menghubungkan VM ke jaringan (baik ke host maupun ke internet), diatur lewat mode jaringan seperti NAT atau Bridged (dibahas di bagian Networking).

ISO & Virtual CD/DVD

ISO adalah file "cetakan" sistem operasi (misalnya Ubuntu Server) yang biasanya diunduh dari internet. File ISO ini "dimasukkan" ke Virtual CD/DVD drive milik VM, seolah kamu memasukkan kepingan DVD instalasi ke komputer sungguhan.

Shared Folder

Folder khusus yang bisa diakses bersama oleh host dan VM, memudahkan memindahkan file antara laptopmu dan sistem di dalam VM tanpa perlu internet.

USB

Pengaturan yang memungkinkan VM mengakses perangkat USB yang tersambung ke host, seperti flashdisk atau perangkat lain.

Display

Pengaturan tampilan layar virtual VM, termasuk jumlah memori video (VRAM) yang dialokasikan untuk menampilkan grafis VM.

Boot Order

Urutan perangkat yang dicoba VM saat pertama kali dinyalakan (misalnya: coba boot dari Virtual CD/DVD dulu, baru dari Virtual Disk) — penting diatur benar saat instalasi sistem operasi baru.

Contoh Konfigurasi VM Sederhana untuk Belajar Ubuntu Server

vCPU: 2 core • vRAM: 2 GB • Virtual Disk: 20–25 GB • Network Adapter: NAT • Virtual CD/DVD: ISO Ubuntu Server • Boot Order: Virtual CD/DVD lebih dulu dari Virtual Disk (saat instalasi pertama kali).

6. Oracle VirtualBox

Oracle VirtualBox adalah software hypervisor Type 2 yang bersifat gratis dan open source, memungkinkan siapa saja membuat dan menjalankan Virtual Machine di atas Windows, macOS, maupun Linux. VirtualBox pertama kali dikembangkan oleh perusahaan Jerman bernama Innotek, sebelum akhirnya dikelola oleh Oracle Corporation.

Kelebihan:

  • Gratis sepenuhnya, tidak perlu membeli lisensi.
  • Ringan dan mudah dipasang, cocok untuk laptop dengan spesifikasi standar.
  • Mendukung banyak sistem operasi tamu (Ubuntu, Debian, Windows, dan lainnya).
  • Dokumentasi resmi lengkap dan komunitas besar, memudahkan mencari solusi saat ada kendala.

Kekurangan:

  • Performa sedikit lebih rendah dibanding hypervisor Type 1 untuk beban kerja sangat berat.
  • Beberapa fitur lanjutan (misalnya dukungan grafis 3D) belum sekuat software berbayar.

Kapan digunakan?

VirtualBox sangat cocok untuk kebutuhan belajar, seperti yang akan kamu lakukan di kelas ASJ ini — membuat VM Ubuntu Server untuk praktik konfigurasi tanpa risiko merusak laptop pribadi.

Istilah Penting di VirtualBox

New — tombol untuk membuat Virtual Machine baru dari awal.
Start — tombol untuk menyalakan/menjalankan VM yang sudah dibuat.
Settings — menu untuk mengatur konfigurasi VM (RAM, CPU, storage, dll).
Storage — bagian pengaturan untuk mengatur virtual disk dan ISO.
Network — bagian pengaturan untuk memilih mode jaringan VM.
Snapshot — fitur menyimpan kondisi VM pada waktu tertentu.
Clone — fitur menduplikasi VM menjadi VM baru.

7. VMware Workstation

VMware Workstation adalah software hypervisor Type 2 buatan VMware (kini bagian dari Broadcom), salah satu perusahaan pionir teknologi virtualisasi sejak akhir 1990-an. VMware Workstation Pro sempat berbayar, namun sejak beberapa tahun terakhir tersedia versi gratis untuk penggunaan pribadi/non-komersial.

Kelebihan:

  • Performa dan stabilitas sangat baik, terutama untuk VM dengan beban kerja berat.
  • Dukungan snapshot dan fitur networking yang matang dan andal.
  • Banyak dipakai di lingkungan profesional/enterprise, sehingga skill ini relevan untuk dunia kerja.

Kekurangan:

  • Ukuran instalasi lebih besar dibanding VirtualBox.
  • Beberapa fitur lanjutan tetap memerlukan lisensi berbayar (versi Pro).

Penggunaan untuk lab virtual

VMware Workstation sering dipakai di dunia industri untuk membangun lab virtual pengujian software sebelum diterapkan ke server produksi sungguhan, karena stabilitasnya yang tinggi.

Perbedaan mendasar dengan VirtualBox: Secara konsep keduanya sama-sama hypervisor Type 2 dengan fitur inti serupa (VM, snapshot, clone, networking). Perbedaan utamanya ada pada performa, harga/lisensi, dan detail antarmuka — bukan pada konsep dasar virtualisasi yang kamu pelajari di bab ini.

9. Snapshot

Snapshot adalah fitur yang menyimpan "kondisi" sebuah Virtual Machine pada waktu tertentu — termasuk isi disk, konfigurasi, dan status sistem saat itu — sehingga kamu bisa kembali ke kondisi tersebut kapan pun dibutuhkan.

Analogi: Snapshot itu seperti save point dalam sebuah game. Sebelum menghadapi "boss" yang berisiko (misalnya konfigurasi server yang rumit), kamu simpan progres game dulu. Kalau gagal atau kalah, kamu tinggal load lagi dari save point tadi — tidak perlu main dari awal.

Contoh Penerapan:

Siswa akan melakukan konfigurasi Ubuntu Server yang berisiko (misalnya mengatur firewall atau menghapus user). Sebelum memulai konfigurasi tersebut, siswa membuat Snapshot terlebih dahulu. Jika konfigurasi ternyata gagal atau sistem menjadi rusak, siswa cukup mengembalikan VM ke kondisi Snapshot tadi — dalam hitungan detik, tanpa perlu install ulang dari nol.

  • Kapan membuat snapshot? Sebelum melakukan perubahan besar atau berisiko pada VM (update besar, konfigurasi baru, eksperimen).
  • Kapan menggunakan snapshot? Saat perubahan yang dilakukan ternyata gagal atau merusak sistem, dan kamu ingin kembali ke kondisi sebelumnya.
  • Kelebihan: cepat dibuat, mudah dikembalikan, sangat membantu proses belajar dan eksperimen.
  • Keterbatasan: snapshot tersimpan di storage host yang sama dengan VM aslinya — jika harddisk host rusak total, snapshot ikut hilang.

Penting: Snapshot BUKAN pengganti Backup!

Backup adalah salinan data yang disimpan terpisah dari sistem aslinya (misalnya di harddisk lain atau cloud), sedangkan snapshot biasanya tersimpan menyatu dengan VM di storage host yang sama. Snapshot cocok untuk "uji coba cepat", tapi tetap butuh backup terpisah untuk perlindungan data jangka panjang.

10. Clone

Clone adalah fitur untuk menduplikasi sebuah Virtual Machine yang sudah ada menjadi VM baru yang identik, lengkap dengan sistem operasi dan konfigurasinya.

Contoh Penerapan:

Bayangkan kamu sudah membuat satu VM Ubuntu Server yang sudah dikonfigurasi dengan lengkap (update sistem, user, package dasar sudah terpasang). Sekarang kamu ingin membuat 5 VM lain dengan konfigurasi dasar yang persis sama untuk simulasi jaringan. Daripada mengulang instalasi dari nol sebanyak 5 kali (yang memakan waktu berjam-jam), kamu cukup melakukan Clone pada VM pertama sebanyak 5 kali — jauh lebih cepat dan konsisten.

Full Clone vs Linked Clone

Full Clone

Menyalin seluruh data VM asli menjadi file independen yang terpisah sepenuhnya. VM hasil clone bisa berjalan sendiri walau VM aslinya dihapus, namun memakan ruang penyimpanan lebih besar dan proses pembuatannya lebih lama.

Linked Clone

VM hasil clone tetap bergantung pada file VM induknya, dan hanya menyimpan "perbedaan" data baru. Prosesnya jauh lebih cepat dan hemat ruang, namun VM induk tidak boleh dihapus selama linked clone masih dipakai.

Untuk kebutuhan belajar di kelas ASJ, Full Clone lebih direkomendasikan karena lebih sederhana untuk dipahami pemula dan tidak bergantung pada VM lain.

11. Resource Virtual Machine & Over-Allocation

Setiap Virtual Machine yang berjalan tetap menggunakan resource dari komputer fisik (host) tempatnya berjalan — mencakup CPU, RAM, storage, display/GPU, dan network. VM tidak menciptakan resource baru dari udara; ia hanya "meminjam" sebagian dari resource host.

Konsep Over-Allocation

Over-allocation terjadi ketika total resource (terutama RAM) yang dialokasikan ke semua VM yang berjalan bersamaan melebihi kapasitas fisik yang sebenarnya dimiliki host.

Contoh Perhitungan

Laptop: CPU 4 Core, RAM 8 GB

Kemudian dibuat 3 VM sekaligus, masing-masing diberi RAM 2 GB (total 6 GB untuk VM) — sisa 2 GB untuk sistem operasi host itu sendiri. Kondisi ini masih realistis, karena OS host tetap kebagian resource untuk berjalan normal.

Namun jika 3 VM tersebut masing-masing diberi RAM 4 GB (total 12 GB), padahal RAM fisik hanya 8 GB, maka terjadi over-allocation. Akibatnya: host menjadi sangat lambat, VM bisa macet (freeze), bahkan sistem host berisiko crash karena kehabisan memori nyata.

Rekomendasi Konfigurasi Realistis untuk Laptop Siswa

Untuk laptop dengan RAM 8 GB, sebaiknya hanya menjalankan 1 VM aktif dalam satu waktu dengan alokasi sekitar 2 GB RAM dan 2 vCPU, menyisakan cukup resource untuk sistem operasi host dan aplikasi lain (browser, VirtualBox itu sendiri, dll). Jika laptop punya RAM 16 GB ke atas, menjalankan 2 VM ringan secara bersamaan (misalnya untuk simulasi client-server) masih realistis dilakukan.

12. Networking pada Virtual Machine

Karena mata pelajaran ini adalah Administrasi Sistem Jaringan, memahami cara VM terhubung ke jaringan adalah bagian yang sangat penting — dan akan sangat berguna saat kamu mulai konfigurasi server jaringan di bab-bab berikutnya.

NAT (Network Address Translation)

Pengertian: Mode paling sederhana dan default di VirtualBox. VM "menumpang" koneksi internet host, tapi tidak terlihat sebagai perangkat terpisah oleh jaringan luar.

Cara kerja: VM → Host → Internet. Semua permintaan dari VM diteruskan lewat host, seolah VM "bersembunyi" di belakang host.

Kapan digunakan: Saat VM hanya perlu akses internet untuk update/download, tanpa perlu diakses balik oleh komputer lain.

Contoh: VM Ubuntu Server ingin menjalankan apt update untuk mengunduh paket dari internet.

Bridged Adapter

Pengertian: Membuat VM seolah-olah menjadi perangkat fisik terpisah yang terhubung langsung ke jaringan/router yang sama dengan host.

Cara kerja: VM → Router/LAN → Internet. VM mendapat alamat IP sendiri di jaringan yang sama seperti laptop/HP lain di rumah/sekolah.

Kapan digunakan: Saat VM perlu bisa diakses langsung oleh komputer lain di jaringan yang sama, misalnya untuk praktik mengakses server dari client lain.

Contoh: VM Ubuntu Server dijadikan web server, dan ingin diakses dari HP siswa lain yang terhubung ke Wi-Fi sekolah yang sama.

Host-Only Adapter

Pengertian: Membuat jaringan privat yang hanya menghubungkan VM dengan host saja, tanpa akses ke internet maupun jaringan fisik luar.

Cara kerja: VM ↔ Host. Koneksi hanya terjadi dua arah antara VM dan laptop/PC-mu sendiri.

Kapan digunakan: Saat kamu ingin mengakses VM dari host (misalnya lewat SSH) tanpa perlu VM terhubung ke internet sama sekali, cocok untuk latihan yang sifatnya privat/tertutup.

Contoh: Mengakses VM Ubuntu Server dari Terminal di laptop host untuk latihan perintah dasar Linux.

Internal Network

Pengertian: Membuat jaringan privat yang hanya menghubungkan antar-VM, tanpa melibatkan host maupun jaringan luar sama sekali.

Cara kerja: VM 1 ↔ VM 2 ↔ VM 3 (host tidak ikut dalam jaringan ini).

Kapan digunakan: Saat kamu ingin simulasi jaringan tertutup antara beberapa VM saja, misalnya simulasi server-client tanpa risiko keluar ke jaringan sekolah.

Contoh: Dua VM (satu jadi server, satu jadi client) saling terhubung untuk latihan konfigurasi DHCP/DNS tanpa menyentuh jaringan sekolah sama sekali.

Catatan penting: Pemilihan mode jaringan ini akan sangat menentukan saat kamu mulai belajar konfigurasi DHCP Server, DNS Server, dan Web Server di bab-bab selanjutnya — pastikan kamu benar-benar paham perbedaan keempatnya sebelum lanjut ke Bab 4.

13. System Requirement

Sebelum membuat Virtual Machine, ada beberapa hal yang perlu dipastikan pada komputer/laptop yang akan dipakai:

  • CPU mendukung virtualisasi — hampir semua CPU modern (dalam 10 tahun terakhir) sudah mendukung fitur virtualisasi hardware.
  • RAM cukup — idealnya minimal 8 GB RAM total, agar VM dan host sama-sama bisa berjalan nyaman.
  • Storage cukup — sisakan minimal 30–40 GB ruang kosong untuk menampung file ISO dan virtual disk.
  • Virtualization Technology aktif — fitur hardware yang harus diaktifkan agar hypervisor bisa bekerja optimal.
  • Intel VT-x — nama fitur virtualisasi hardware pada prosesor Intel.
  • AMD-V / AMD SVM — nama fitur virtualisasi hardware yang setara pada prosesor AMD.

Fitur Intel VT-x/AMD-V biasanya sudah aktif secara default pada kebanyakan laptop modern. Jika VirtualBox menampilkan peringatan terkait virtualisasi tidak aktif, fitur ini perlu diaktifkan lewat menu pengaturan BIOS/UEFI laptop. Karena nama menu dan cara masuk BIOS/UEFI berbeda-beda tergantung merek dan tipe laptop, tanyakan langsung kepada Bapak Khalid Nabawi, S.Kom. jika mengalami kendala ini saat praktik.

14. Tahukah Kamu?

  1. Konsep "virtual machine" sebenarnya sudah ada sejak era komputer mainframe IBM pada tahun 1960-an, jauh sebelum komputer pribadi seperti sekarang ada.
  2. Oracle VirtualBox awalnya dikembangkan oleh perusahaan Jerman bernama Innotek pada tahun 2007, sebelum diakuisisi Sun Microsystems (2008) dan kemudian Oracle Corporation (2010).
  3. VMware didirikan pada tahun 1998 dan merilis VMware Workstation pertamanya pada tahun 1999, menjadikannya salah satu pionir virtualisasi desktop di dunia.
  4. Teknologi virtualisasi hardware Intel VT-x diperkenalkan pada tahun 2005, disusul teknologi setara dari AMD (AMD-V) pada tahun 2006.
  5. Hypervisor Type 1 disebut juga "bare-metal hypervisor" karena istilah ini menggambarkan software yang terpasang langsung di atas hardware ("logam telanjang"), tanpa OS host di antaranya.
  6. Xen, salah satu hypervisor open source yang populer di dunia cloud computing, awalnya dikembangkan oleh peneliti University of Cambridge pada tahun 2003.
  7. KVM (Kernel-based Virtual Machine) telah menjadi bagian resmi dari kernel Linux sejak tahun 2007, membuat Linux memiliki kemampuan hypervisor bawaan.
  8. Layanan cloud computing raksasa seperti Amazon Web Services (AWS) dan Google Cloud pada dasarnya dibangun di atas jutaan Virtual Machine yang berjalan di atas hypervisor Type 1 di data center mereka.
  9. Snapshot pada VM sebenarnya hanya menyimpan "perbedaan" (delta) dari kondisi disk saat itu, bukan menyalin ulang seluruh isi disk dari awal — itulah sebabnya proses pembuatan snapshot terasa sangat cepat.
  10. Selain virtualisasi berbasis VM, kini berkembang pula teknologi container (seperti Docker) yang jauh lebih ringan karena berbagi kernel sistem operasi host, meski tetap terinspirasi dari konsep isolasi sistem yang sama seperti virtualisasi.

15. Tips Administrator

  1. Jangan memberikan seluruh RAM host kepada satu VM — sisakan cukup RAM agar sistem operasi host tetap berjalan lancar.
  2. Jangan asal menghapus virtual disk, karena seluruh data dan sistem operasi di dalam VM ikut hilang permanen.
  3. Buat Snapshot sebelum melakukan eksperimen atau konfigurasi besar yang berisiko gagal.
  4. Gunakan nama VM yang jelas dan deskriptif (misalnya "Ubuntu-Server-DHCP") agar tidak bingung saat memiliki banyak VM.
  5. Dokumentasikan konfigurasi setiap VM (vCPU, vRAM, mode jaringan) agar mudah diingat atau dijelaskan ke orang lain.
  6. Matikan VM dengan benar lewat perintah shutdown di dalam sistem operasi guest, bukan langsung menutup jendela VirtualBox secara paksa.
  7. Simpan file ISO di lokasi yang mudah ditemukan kembali, karena akan sering dipakai ulang untuk membuat VM baru.
  8. Periksa mode jaringan VM sebelum praktik yang melibatkan koneksi antar-perangkat, agar tidak bingung saat VM "tidak bisa diakses".
  9. Hapus snapshot lama yang sudah tidak diperlukan secara berkala, karena snapshot yang menumpuk memakan banyak ruang storage.
  10. Selalu cek sisa ruang penyimpanan host sebelum membuat virtual disk baru, agar proses instalasi tidak gagal di tengah jalan.

16. Kesalahan Pemula

Memberi RAM VM terlalu besar. Penyebab: ingin VM terasa cepat. Solusi: alokasikan RAM secukupnya dan sisakan untuk host, sesuai kapasitas RAM fisik yang tersedia.
Lupa memasukkan ISO sebelum menjalankan VM. Penyebab: terburu-buru saat setup awal. Solusi: pastikan ISO sudah terpasang di Storage sebelum menekan Start pertama kali.
Salah memilih mode jaringan. Penyebab: tidak memahami perbedaan NAT, Bridged, dan Host-Only. Solusi: pahami dulu kebutuhan koneksi VM sebelum memilih mode jaringan.
Tidak membuat Snapshot sebelum eksperimen berisiko. Penyebab: merasa yakin konfigurasi akan berhasil. Solusi: biasakan membuat Snapshot sebagai kebiasaan rutin sebelum perubahan besar.
Mematikan VM secara paksa (force shutdown) terus-menerus. Penyebab: tidak sabar menunggu proses shutdown normal. Solusi: gunakan perintah shutdown resmi dari dalam sistem operasi guest.
Menjalankan terlalu banyak VM sekaligus. Penyebab: tidak memperhitungkan kapasitas RAM/CPU host. Solusi: jalankan hanya VM yang benar-benar dibutuhkan dalam satu waktu (hindari over-allocation).
Menghapus virtual disk tanpa yakin. Penyebab: ingin menghemat ruang penyimpanan tanpa cek ulang. Solusi: pastikan data di VM sudah tidak diperlukan lagi sebelum menghapus.
Tidak memberi nama VM yang jelas. Penyebab: terburu-buru saat membuat banyak VM. Solusi: biasakan memberi nama deskriptif sejak awal pembuatan VM.
Mengira Snapshot sama dengan Backup. Penyebab: belum memahami perbedaan konsep keduanya. Solusi: pelajari kembali bahwa snapshot bukan pengganti backup terpisah.
Panik saat VM terasa lambat tanpa mengecek penyebabnya. Penyebab: langsung menyalahkan software tanpa investigasi. Solusi: cek dulu alokasi RAM/CPU dan jumlah VM yang berjalan bersamaan sebelum mengambil kesimpulan.

18. Praktikum — Membuat Komputer Virtual Pertama

Tujuan: Siswa mampu membuat Virtual Machine pertamanya dan menjalankannya dengan benar menggunakan Oracle VirtualBox.

Alat: Laptop/PC dengan RAM minimal 8 GB, Oracle VirtualBox (atau VMware Workstation), file ISO Linux yang sesuai untuk pembelajaran (misalnya Ubuntu Server).

Langkah Praktikum:

  1. Mengecek spesifikasi komputer — pastikan RAM, CPU, dan sisa storage laptop mencukupi sesuai System Requirement pada Materi 13.
  2. Memastikan virtualisasi tersedia — cek apakah fitur Intel VT-x/AMD-V sudah aktif (bisa dicek lewat Task Manager pada Windows, bagian Performance → CPU → Virtualization).
  3. Membuka VirtualBox/VMware — jalankan aplikasi yang sudah terinstal di laptop.
  4. Membuat VM baru — klik tombol New untuk memulai wizard pembuatan VM.
  5. Memberikan nama VM — gunakan nama deskriptif, misalnya "Ubuntu-Server-Praktikum1".
  6. Memilih ISO — arahkan ke lokasi file ISO Ubuntu Server yang sudah diunduh sebelumnya.
  7. Mengatur RAM — alokasikan sekitar 2 GB (2048 MB) sesuai rekomendasi realistis dari Materi 11.
  8. Mengatur CPU — alokasikan 2 vCPU agar proses instalasi dan konfigurasi terasa cukup responsif.
  9. Membuat virtual disk — buat virtual disk baru dengan kapasitas sekitar 20–25 GB.
  10. Mengatur Network — pilih mode NAT untuk tahap awal ini, agar VM bisa mengakses internet untuk update sistem.
  11. Menjalankan VM — klik tombol Start untuk menyalakan VM yang baru dibuat.
  12. Mengamati proses boot — perhatikan layar VM saat mulai memuat installer Ubuntu Server dari ISO, catat tahapan yang muncul.
  13. Mematikan VM dengan benar — gunakan opsi shutdown resmi (bukan menutup paksa jendela VirtualBox) untuk mengakhiri sesi praktikum.

Hasil yang Diharapkan: Siswa berhasil membuat satu Virtual Machine dari awal hingga bisa dinyalakan dan menampilkan proses boot installer Ubuntu Server, sebagai persiapan langsung menuju praktik instalasi penuh di Bab 4.

20. Ringkasan

  • Virtualisasi memungkinkan satu hardware fisik (Host) menjalankan banyak komputer virtual (Guest) sekaligus, mengubah cara kita membangun dan belajar server.
  • Hypervisor adalah software pengatur Virtual Machine, terbagi menjadi Type 1 (bare-metal, untuk server produksi) dan Type 2 (hosted, untuk belajar/desktop seperti VirtualBox dan VMware Workstation).
  • Setiap VM memiliki komponen virtual sendiri: vCPU, vRAM, Virtual Disk, dan Virtual Network Adapter, yang semuanya "meminjam" resource dari host.
  • Snapshot menyimpan kondisi VM pada waktu tertentu (seperti save point game) namun bukan pengganti backup, sedangkan Clone menduplikasi VM untuk mempercepat pembuatan VM baru yang serupa.
  • Over-allocation terjadi jika resource yang dialokasikan ke semua VM melebihi kapasitas fisik host, menyebabkan sistem menjadi lambat.
  • Empat mode jaringan VM utama: NAT (internet lewat host), Bridged (VM jadi perangkat terpisah di jaringan fisik), Host-Only (VM hanya terhubung ke host), dan Internal Network (hanya antar-VM).

24. Glosarium

Virtualisasi — teknologi membagi satu hardware fisik menjadi beberapa komputer virtual.

Virtual Machine (VM) — komputer virtual yang berjalan di atas komputer fisik.

Host — komputer fisik yang menjalankan Virtual Machine.

Guest — sistem operasi yang berjalan di dalam Virtual Machine.

Hypervisor — software pengatur dan pencipta Virtual Machine.

Type 1 Hypervisor — hypervisor bare-metal, berjalan langsung di atas hardware.

Type 2 Hypervisor — hypervisor hosted, berjalan di atas sistem operasi host.

Oracle VirtualBox — software hypervisor Type 2 gratis dan open source.

VMware Workstation — software hypervisor Type 2 buatan VMware/Broadcom.

vCPU — prosesor virtual yang dialokasikan untuk VM.

vRAM — memori virtual yang dialokasikan untuk VM.

Virtual Disk — file yang berperan sebagai harddisk VM.

Virtual Network Adapter — kartu jaringan virtual milik VM.

ISO — file cetakan sistem operasi yang dipakai untuk instalasi VM.

Shared Folder — folder yang dapat diakses bersama oleh host dan VM.

Boot Order — urutan perangkat yang dicoba VM saat dinyalakan.

Snapshot — fitur menyimpan kondisi VM pada waktu tertentu.

Clone — fitur menduplikasi VM menjadi VM baru.

Full Clone — hasil clone yang menyalin seluruh data secara independen.

Linked Clone — hasil clone yang tetap bergantung pada VM induk.

Over-allocation — alokasi resource ke VM yang melebihi kapasitas fisik host.

NAT — mode jaringan VM lewat host tanpa terlihat jaringan luar.

Bridged Adapter — mode jaringan VM sebagai perangkat terpisah di jaringan fisik.

Host-Only Adapter — mode jaringan yang hanya menghubungkan VM dengan host.

Internal Network — mode jaringan yang hanya menghubungkan antar-VM.

Isolasi Sistem — pemisahan antar VM agar masalah di satu VM tidak menyebar.

Intel VT-x — fitur virtualisasi hardware pada prosesor Intel.

AMD-V / AMD SVM — fitur virtualisasi hardware pada prosesor AMD.

Physical Machine — komputer fisik sungguhan.

Data Center — fasilitas berisi banyak server yang menjalankan ribuan VM.
